## Key columns

- `occupations_en.csv`: `conceptType (=Occupation), conceptUri (…/esco/occupation/<UUID>),
  iscoGroup (e.g. 2654), preferredLabel, altLabels, hiddenLabels (newline-separated),
  status (all released in v1.2.1, obsolete filtered if present),
  modifiedDate, regulatedProfessionNote, scopeNote, definition, description,
  code (e.g. 2654.1.7), naceCode, inScheme`.
- `ISCOGroups_en.csv`: `conceptUri (…/esco/isco/C<code>), code (0…0110…),
  preferredLabel, status, altLabels, description`.
- `broaderRelationsOccPillar_en.csv`: `conceptType, conceptUri, conceptLabel,
  broaderType, broaderUri, broaderLabel`.
- `occupationSkillRelations_en.csv`: `occupationUri, occupationLabel, relationType,
  skillType, skillUri (…/esco/skill/<UUID>, format-validated only, no cross-pillar join),
  skillLabel`.

## Hierarchy semantics (full ISCO path)

`ISCO major (C0–C9) > … > ISCO unit group > ESCO occupation (→ narrower occupation?)`.
Poly-hierarchical: canonical path = longest root path, ties broken by URI tuple
(same rule as the skills pipeline). `isco_major` = root single-digit code.
`terminal_isco_uri` = nearest ISCO ancestor. Occupation→occupation edges are kept
in the path with `node_type=occupation`.
